# Deterministic risk engine, revision 1

Inputs are decimal strings, UUID version references, a server timestamp, validated account observation, immutable instrument specification, current risk plan, and account/day ledger. Direction is LONG or SHORT; model is OB_FIRST_TOUCH or OTE. No boolean generated by AI can bypass a numeric/session rule.

Risk budget = floor(equity × requested risk percent / 100, currency minor units).
Stop distance = abs(entry − stop). Tick distance = stop distance / tick size.
Risk per quantity = tick distance × tick value per quantity in account currency.
Quantity = floor((risk budget / risk per quantity) / quantity step) × quantity step.
Nominal risk = quantity × risk per quantity. Never round quantity upward.
Planned RR = abs(target − entry) / abs(entry − stop). Compare exact values before display rounding.
Pip distance is nullable when the instrument has no meaningful pip convention.
Future realized R = net realized account-currency P&L / original locked nominal risk; require recorded costs and realized fills or explicitly identify missing costs. Never change the denominator when a stop moves.

Reject nonfinite/nonpositive inputs, missing stop, incorrect LONG/SHORT stop/target geometry, off-tick prices, unsupported instrument/currency, unconfirmed contract assumptions, unknown execution models, excessive requested risk, quantity below minimum, exhausted daily slots, duplicate exact plans, and Dead Pool. RR threshold follows the versioned BLOCK/WARN setting. Explicit strategy contradictions block. News restriction follows versioned BLOCK/WARN; unknown news emits a warning. No fabricated calendar data.

Fixed UTC−05:00 windows: ASIA [18:00,01:00), JUDAS [01:00,02:00), ACTIVE_KILL_ZONE [02:00,12:00), DEAD_POOL [12:00,18:00). Asia/Judas warn: the original strategy explicitly prohibits Dead Pool but does not impose a blanket ban on every other period. No extra weekend prohibition is invented.

Daily eligibility counts executed trades plus active plan reservations. The first slice reserves conservatively at lock and does not implement reservation release. Daily nominal risk consumed sums original locked risk on the strategy date. Optional money caps compare consumed plus proposed risk with cap. Optional daily loss limit also compares recorded gross losses plus outstanding reserved exposure; if loss data is absent, a configured loss limit fails closed. Profits do not replenish risk. Defaults leave unspecified caps unconfigured and disclose that limitation.

The lock transaction locks the account row before reading observations, effective versions and daily usage. It computes from server time, writes immutable version links, original inputs and the risk result, then PLAN_LOCKED. An idempotency UUID identifies one request: identical replay returns the existing record; changed content is rejected. Exact entry/stop/target/model/direction/instrument repeats on the same day are blocked. Similar-looking chart duplicates are outside this slice.

Data freshness: require a manual account observation from the current fixed UTC−5 strategy day. An old observation remains in history but cannot size a new locked plan until reconfirmed. Equity/balance and monetary caps reject excess fractional cents rather than silently rounding configuration upward. PostgreSQL uses exact integer quotient for quantity steps; both implementations verify nominal risk never exceeds the budget.

Warnings keep the risk decision separate from setup assessment. A lock is a record and reservation, not permission to execute. In this slice setup status is NOT_EVALUATED; the UI must never label a trade APPROVED by ICT without the later evidence review.

Tests cover monetary and size rounding, both directions, tiny stops, zero/negative/invalid numbers, off-grid prices, RR boundaries, min quantity, missing stop, max trades, risk caps, news unknown/restricted, all session boundaries and DST dates, idempotency, strategy/risk version links, effective-day changes, RLS, immutable plans and event order. PostgreSQL and TypeScript run common parity cases to detect drift.
