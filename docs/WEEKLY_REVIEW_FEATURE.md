## Selected-week policy and exact context

A calendar week starts Monday 00:00 inclusive and ends next Monday 00:00 exclusive in the application's fixed UTC−5 convention, always 05:00 UTC, including DST dates. Selection of any day normalizes to its Monday. Default: previous completed week. Current/future weeks are blocked. The UI shows Monday/Sunday dates plus exact UTC boundaries. Supported input dates start 2000-01-03 and end 2099-12-31.

Scope is completed trades whose persisted exit timestamp falls in that account/week. Database queries explicitly filter account, ownership and dates; they never load the full Journal as AI context. Original plans/executions may predate the week when necessary to describe a trade closed inside it.

The provider receives:
- immutable original plan: lock/trading day, instrument, direction, entry model, planned entry/stop/target, risk percent, news/narrative, contract confirmation, original nominal risk;
- each trade's original strategy ID/version/rules/written rules and risk-plan ID/version/effective date/limits/policies;
- saved deterministic Risk Engine status, session, version references, issues, calculations and rule results when present;
- actual entry/quantity/time, exit/time, fees, net P&L, persisted realized R/outcome and original planned quantities/risk;
- allowlisted notes/events/manual tag payloads that both occurred and were recorded inside the selected week, attached only to the selected trades;
- the existing domain analytics metrics result for exactly those completed rows (including existing sample label and equity/drawdown sequence), without new formulas;
- period, capture time, scope statement, deterministic sample caveat and allowed source references.

No screenshots, storage paths, prior AI results, open trades, balances/equity observations, unrelated trades/months, predecessor history or other accounts are sent. The latest-tags fields in the analytics view are excluded because later tag revisions could fall outside the selected week. Only relevant in-period manual-tag events are included.

Limits: 40 completed trades, 200 relevant events, 96,000 UTF-8 context bytes, and the provider's 24,000-token check including prompt/schema. Oversized weeks fail closed; there is no silent sampling or truncation. Empty weeks cannot dispatch. These caps are explicit initial limits, not claims that all possible weekly records fit.

## Interpretation and deterministic authority

TRADING OS FACTS are rendered from the saved server snapshot, never generated by AI. The nine AI sections are:
WEEK SUMMARY; PROCESS QUALITY; RULE ADHERENCE; SETUP / MODEL PATTERNS; EXECUTION MISTAKES; BEHAVIORAL PATTERNS; WHAT IMPROVED; WHAT NEEDS ATTENTION; FOCUS FOR NEXT WEEK.

The UI identifies all of them as AI INTERPRETATION / ADVISORY ONLY. Strict output validation rejects extra authority/mutation fields, foreign references and explicit trade directives. The prompt prohibits invented market conditions/trades/rules, behavioral diagnoses and unseen prior-week comparisons. Missing evidence and inability to establish improvement must be stated. The application always renders its own small-sample caveat, independent of model compliance.

Risk Engine, position sizing, RR, trade locking, realized R, EDGE formulas, session rules, auth/authorization and screenshot security changed: NO. Existing metrics are called rather than reimplemented.

## Persistence, ownership and RLS

New additive migration: supabase/migrations/0011_weekly_ai_reviews.sql.

Existing 0009 history requires a single closed trade_plan foreign key; existing 0010 requires a single unlocked proposal and permits only proposal operations. Reusing either would require weakening its identity/semantics or creating artificial records. Therefore 0011 is necessary.

Tables:
- weekly_ai_reviews: owner/account/week, immutable facts/hash, operation and contract snapshot, creation/deadline.
- weekly_ai_review_results: one immutable COMPLETED/FAILED result per request, interpretation/error/raw output and exact reservation link.

Service-only RPCs:
- start_weekly_ai_review
- authorize_weekly_ai_review
- finish_weekly_ai_review

Owner-only SELECT RLS, composite ownership foreign keys and mutation-rejection triggers protect both tables. Public/anonymous/authenticated/service roles cannot directly write. Browser roles cannot execute privileged RPCs. The account row serializes starts for a selected week; replay returns false and never spends again. A fresh request ID appends a new version. Existing history stays readable after opt-out.

0011 was applied only inside disposable PGlite test databases. No hosted migrations were applied. No changes to migrations 0001–0010 or the shared accounting RPCs.
